## 1. 问题与背景
软件漏洞持续威胁现代数字基础设施，而传统静态应用安全测试（SAST）工具存在高误报率，削弱开发者对安全警告的信任。随着代码库复杂度增加，传统检测手段难以全面覆盖，迫切需要新的自动化漏洞发现方法。近年来大型语言模型（LLM）在代码理解上展现潜力，但单一模型易产生幻觉，缺乏针对特定组织环境的漏洞模式认知，这使得如何高效、精准地发现漏洞成为核心挑战。  

## 2. 核心思路 / 方法
TitanCA通过将多个LLM驱动的智能体编排成四模块流水线（Matcher、Filter、Inspector、Adapter）实现漏洞发现，每个模块递进过滤假阳性并增强检测可信度。Matcher模块基于已知漏洞函数数据库进行相似性匹配，Filter模块使用结构化推理和强化学习优化误报率，Inspector模块通过多智能体“模拟法庭”方式进行对抗式审查，Adapter模块在新组织环境中进行域特定适配并建立反馈循环提升精度。这种模块化、多智能体编排方式相比单一模型方法更能平衡召回率与精确度，同时引入域知识解决组织特定漏洞模式问题。  

## 3. 结果与结论
在开源软件应用中，TitanCA分析了超过127,000个GitHub仓库的代码，发现203个零日漏洞，并产生118个CVE。实验表明，这种多智能体分层流水线的方式在漏洞发现上显著优于传统SAST工具，并能有效降低误报率。研究结论是，通过结构化编排LLM智能体，自动化漏洞发现可以成为人类安全专家的重要补充，提升漏洞检测的效率与可信度。  

## 4. 局限与适用边界
TitanCA目前主要针对函数级别检测，初期阶段专注于开发者编写的代码，尚未扩展到AI生成代码或代码修复。域适配模块依赖目标组织环境样本数据，其效果可能受部署环境和编程习惯差异限制。

## Abstract
Software vulnerabilities remain one of the most persistent threats to modern digital infrastructure. While static application security testing (SAST) tools have long served as the first line of defense, they suffer from high false-positive rates. This article presents TitanCA, a collaborative project between Singapore Management University and GovTech Singapore that orchestrates multiple large language model (LLM)-powered agents into a unified vulnerability discovery pipeline. Applied in open-source software, TitanCA has discovered 203 confirmed zero-day vulnerabilities and yielded 118 CVEs. We describe the four-module architecture, i.e., matching, filtering, inspection, and adaptation, and share key lessons from building and deploying an LLM-based vulnerability discovery solution in practice.

## 4. 方法详解

### 四模块管道
TitanCA的四模块管道协同工作，分别在不同阶段增强检测精度并减少误报。

- **Module 1: The Matcher (VulCoCo)**
  - 利用已知漏洞数据库（如NVD）和TitanVul数据集，进行函数的相似性匹配。
  - 使用LLM作为语义验证器，确认候选漏洞是否真实。
  
- **Module 2: The Filter (R2Vul)**
  - 应用结构化推理和强化学习优化，减少误报。
  - 使用对比监督方法，识别误导性推理与真实推理之间的区别。

- **Module 3: The Inspector (VulTrial)**
  - 采用多智能体“模拟法庭”模式，模拟多个角色进行对抗式审查，增强漏洞判断的可信度。

- **Module 4: The Adapter (PairVul)**
  - 针对目标组织的编程语言、框架等特点，进行域适配。
  - 通过反馈循环不断提高精度，适应新环境中的漏洞模式。
