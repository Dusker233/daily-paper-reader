## 1. 问题与背景

传统大语言模型将事实知识隐式存储在模型参数中，导致知识难以编辑、删除和追溯，同时长尾事实记忆能力受限。已有 Limited Memory Language Models（LMLM）尝试将事实知识外置到可读、可编辑的知识库中，但基于关系型知识库的方法依赖 Wikipedia 风格的主语-关系-宾语结构，限制了可扩展性和知识覆盖范围。论文关注如何在保留知识外置带来的可控性、可解释性优势的同时，突破关系查询和 Wikipedia 数据依赖的限制。

## 2. 核心思路 / 方法

论文提出 Continuous-Query Limited Memory Language Models（Co-LMLM），将知识库存储形式从关系型三元组改为连续向量键与文本知识值配对的非结构化索引。模型通过 Transformer 隐状态生成连续向量查询，并使用对比学习优化查询向量与知识片段之间的匹配关系，而不是生成额外的文本关系查询。该方法在预训练数据处理中仅标注何时需要检索以及返回哪些知识文本，使检索路径由模型学习决定。相比 Rel-LMLM，Co-LMLM 可以检索更自由的知识片段，降低查询生成成本，并能够扩展到 Wikipedia 之外的通用语料。

## 3. 结果与结论

实验显示，Co-LMLM 在不同模型规模下均优于 Rel-LMLM 和未进行知识外置的标准语言模型，在困惑度（perplexity）和事实准确性方面取得提升。在 360M 参数规模下，Co-LMLM 的困惑度低于使用 40 倍更多训练数据的 HF/SMOLLM2-360M，并且 SimpleQA 验证的事实性能接近 gpt-4o-mini，高于 Claude Sonnet 4.5。论文认为，连续查询机制能够兼顾高效语言建模、事实检索能力以及外部知识库的可编辑和可归因特性。

## 4. 局限与适用边界

论文主要验证了 Co-LMLM 在 Wikipedia 和 FineWeb-Edu 等预训练场景中的效果，其他领域或不同知识分布下的表现从现有文本无法确认。该方法仍依赖外部知识库和检索机制，其实际部署成本、长期维护效果以及更大规模模型中的扩展性仍需要进一步研究。

## Abstract
Limited memory language models (LMLMs) externalize factual knowledge during pretraining to a knowledge base (KB), rather than memorizing it in their weights. During generation, the model then fetches knowledge from the KB as needed. This recently introduced paradigm provides multiple advantages, including knowledge control capabilities that remain beyond conventional LLMs. We propose continuous-query LMLM (CO-LMLM), where the KB pairs continuous keys with textual knowledge values, a significant departure from prior reliance on relational KB and queries. CO-LMLM generates flexible vector queries at minimal cost, while still integrating human-readable and attributable retrieved knowledge into its generation. We pair this design with an annotation pipeline that tags free-form factual spans in arbitrary text, removing prior work's restriction to Wikipedia. Across pretraining on Wikipedia and FineWeb-Edu and at multiple model scales, CO-LMLM outperforms prior LMLMs and vanilla LLMs in both perplexity and factual precision. At 360M scale, this includes lower perplexity than models pretrained on 40x more data, and SimpleQA-verified performance that is in line with gpt-4o-mini and higher than Claude Sonnet 4.5.

## 4.3 Continuous Query

论文最大的改变（Section 3.1）：

模型输出：

```
...
<FACT>
```

不是继续生成文本，而是：

```
last hidden state
```

直接作为：

```
q ∈ R^d
```

随后：

```
Top-1 Dense Retrieval
```

返回：

```
Fact Span
```

插入上下文：

```
<FACT>

Retrieved Fact

</FACT>
```

继续自回归生成。

相比 REL-LMLM：

- 无需生成 Relation；
- 无需 Sentence Encoder；
- Retrieval 成本约为一次额外生成 `<FACT>` token（Section 3.1，Table 13）。

# 6. 局限性与风险

## 假设约束

- 检索依赖准确的 Fact Span 标注质量；若标注错误，知识库质量将直接影响模型表现。
- 模型默认知识可以切分为可检索文本片段，这一假设未覆盖复杂推理或隐式知识。

## 应用边界

- 当前实验主要覆盖 Wikipedia 与 FineWeb-Edu，跨领域知识库（医疗、法律、多模态等）效果尚未验证。
- 检索机制默认返回 Top-1 文本片段，对需要多跳、多证据融合的任务支持有限。

## 潜在风险

- 外部 KB 的维护、版本控制与一致性成为新的系统复杂度来源。
- 大规模向量索引的存储、更新及在线检索成本在工业场景下仍需进一步评估。
- 关于超大规模（如数十亿至更大参数模型）训练与部署收益，正文未充分验证。

## 复现重点

1. **事实标注流水线**
   - 先构建种子标注数据，再训练 BIO Fact Span Annotator 与 Question Generator（Figure 3）。

## 后续研究方向

- 扩展到多跳检索、组合推理及跨文档知识融合，而非单次 Top-1 检索。
- 探索动态更新、增量学习及超大规模知识库下的检索效率与稳定性。

- **性能提升**：Co-LMLM 在困惑度与事实准确率上整体优于 Standard LM 与 REL-LMLM；360M 模型困惑度优于训练数据约 **40×** 更多的 SmolLM2（Figure 4；Table 1）。
