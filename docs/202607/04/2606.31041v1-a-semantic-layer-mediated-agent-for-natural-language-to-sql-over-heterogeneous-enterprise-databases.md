## 1. 问题与背景  
该论文研究的是企业级复杂数据库环境下的自然语言转SQL（NL2SQL）问题。与学术基准不同，真实企业数据库通常包含上百张表、复杂命名规则以及多种SQL方言，使得直接依赖大模型根据原始schema生成SQL非常不稳定。作者指出，该问题的核心困难来自“语义对齐（grounding）”与“SQL结构组合（composition）”的混合耦合，导致单步生成容易出错且难以修复。因此，该问题对于提升企业数据访问自动化与分析效率具有重要意义。

## 2. 核心思路 / 方法  
论文提出一种“语义层中介”的NL2SQL智能体架构，将LLM与物理数据库schema解耦。系统引入语义层，将表抽象为包含维度、指标与业务语义的模型，并通过一种中间表示Semantic Model Query（SMQ）进行查询表达。SMQ再由确定性编译器转换为不同数据库方言下的SQL，从而保证物理层SQL的正确性与一致性。智能体在“单工具think–act循环”中使用SMQ进行探索，再组合生成最终SQL，并支持跨SQLite、BigQuery与Snowflake等多后端执行。与传统方法直接在原始schema上生成SQL相比，该方法通过“语义层+可编译中间表示”显著降低了结构性错误风险。

## 3. 结果与结论  
在Spider2-snow这一包含547个真实企业任务的基准测试中，该方法达到了94.15%的执行准确率。该结果在官方排行榜中位列第三，并显著优于仅依赖schema提示的基线方法。实验表明，引入语义层作为中介能够显著提升复杂NL2SQL任务的鲁棒性与整体性能。

## 4. 局限与适用边界  
该方法的性能高度依赖语义层的质量与人工维护水平，如果语义描述不完善或存在偏差，会直接影响查询效果。同时，SMQ仅覆盖通用分析核心，复杂查询仍需依赖模型生成SQL，其正确性无法完全由系统保证。此外，当前评估主要基于单一benchmark，且存在语义层可能针对评测集过拟合的风险，因此在真实环境中的泛化能力仍需进一步验证。

## Abstract
Natural language-to-SQL (NL2SQL) over real-world enterprise databases remains significantly more challenging than on academic benchmarks. Enterprise schemas often contain hundreds of physical tables with cryptic column names, heterogeneous SQL dialects, and complex analytical workloads requiring nested aggregations, temporal reasoning, and multi-table joins. We present a semantic-layer-mediated NL2SQL agent that decouples semantic intent from physical SQL execution. Rather than generating SQL directly over raw schemas, the agent reasons over a curated semantic layer through a compact intermediate representation called the Semantic Model Query (SMQ). A deterministic compiler translates each SMQ into dialect-specific SQL, providing verified building blocks that the agent composes into the final query. The system employs a constrained think-act loop, supports SQLite, BigQuery, and Snowflake backends, and is integrated into an end-to-end evaluation framework. Using Gemini 3 Pro, the system achieves 94.15% execution accuracy on the 547-task Spider2-snow benchmark, ranking third on the official leaderboard and substantially outperforming schema-only approaches. We describe the system architecture, SMQ representation, agent workflow, evaluation results, and discuss semantic-layer quality and the trade-off between improved grounding and overfitting.

## 4. 方法详解

## 4.1 总体架构
系统由四层组成（Figure 1）：
- Orchestration Tier
- QUVI NL2SQL Agent Service
- SMQ→SQL Deterministic Compiler
- Multi-backend Executor（SQLite / BigQuery / Snowflake）

---

## 4.2 语义层（Semantic Layer）
将物理schema转为业务语义模型：

- Dimensions（维度）：group/filter keys
- Measures（指标）：聚合目标
- Metrics（指标函数）：预定义计算

每个元素包含：
- description（LLM可读语义）
- expr（物理SQL表达式）

> 关键作用：将“列名识别问题”转化为“语义选择问题”

---

## 4.3 SMQ（Semantic Model Query）
结构化中间表示：

```json
{
  "metrics": [...],
  "filters": [...],
  "group_by": [...]
}
```

特点：
- 只覆盖分析核心操作
- 不表达复杂SQL结构（CTE / window / recursive）
- 作为“稳定语义接口”

---

## 4.4 SMQ→SQL编译器
确定性转换：

流程：
- 解析 SMQ
- 映射 semantic element → physical column（expr）
- 自动补 join graph
- 输出 dialect-specific SQL

关键意义：
- SQL正确性从LLM转移到compiler

---

## 4.5 Agent Think–Act Loop
单工具约束 agent：

工具集合：
- getModelDataElements
- convertSmqToSql
- execute

特点：
- 每步仅允许一个tool call
- SMQ用于探索
- SQL执行为终止动作
