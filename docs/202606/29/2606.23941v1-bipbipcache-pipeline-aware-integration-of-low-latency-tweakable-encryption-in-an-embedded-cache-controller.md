## 1. 问题与背景  
本文关注嵌入式与消费级处理器中缓存数据的安全问题，尤其是SRAM缓存中的内容在断电或物理探测下可能以明文形式泄露，从而暴露敏感数据与密钥信息。现有工作更多针对侧信道攻击（如缓存随机化），但对“缓存内容本身未加密”的问题覆盖不足。该问题在IoT与低成本SoC中尤为重要，因为这些系统难以承受高开销的软件加密方案。  

## 2. 核心思路 / 方法  
论文提出BipBipCache，一种直接映射缓存控制器，将低延迟可调分组密码BipBip集成到缓存读写路径中，对缓存数据与标签进行实时加密处理。其核心机制是将64位缓存字拆分为24位明文与40位tweak结构，使BipBip仅处理关键子块，同时保留上下文绑定信息。系统设计包含数据加密、数据解密与标签解密三类流水化模块，并通过流水调度使6周期加密过程与标签解密阶段重叠，从而隐藏部分写延迟。相较传统缓存保护方法，其创新点在于“加密缓存内容与标签”而非仅随机化索引，并实现了流水感知的低延迟集成。  

## 3. 结果与结论  
实验在Xilinx Artix-7 FPGA上实现，综合资源消耗约3356 LUTs，其中加密逻辑占比约79%，验证了硬件可实现性与可接受开销。设计通过官方BipBip参考实现的测试向量验证，并完成端到端硬件运行确认。关键结论是：虽然加密器理论延迟为6周期，但通过流水重叠设计，写入路径的有效额外开销可降低至约3周期，从而实现低延迟缓存加密。  

## 4. 局限与适用边界  
该方案主要保证缓存驻留数据的机密性，但不针对Prime+Probe、Flush+Reload等侧信道攻击，因此无法提供完整微架构安全性。其标签机制本质上是加密绑定而非强认证结构（不提供MAC级完整性保证），安全性依赖密码原语与威胁模型假设。该方法适用于关注物理读出与冷启动攻击的嵌入式系统场景，但不适用于需要完整侧信道防护或强完整性认证的高安全系统。

## Abstract
Consumer and embedded processors store sensitive data in on-chip SRAM caches that remain readable after power loss or physical probing unless ciphertext is maintained in the memory array itself. This paper presents BipBipCache, a direct-mapped cache controller that integrates the BipBip tweakable block cipher (TBC) to encrypt cache data and tags in real time using a C$^3$-style 24+40 bit decomposition of each 64-bit word. We reconstruct the first pipelined hardware BipBip encryptor from a decryptor-centric specification and coordinate it with a 3-cycle decryptor inside the cache datapath.   Our threat model targets confidentiality of cache-resident contents against cold-boot, bus, and SRAM readout attacks. A key architectural result is that 6-cycle encryption latency does not fully translate into 6-cycle write penalty: the first three encryptor stages overlap with tag decryption and hit detection, leaving an effective 3-cycle write commitment after hit verification. We verify encryptor and decryptor correctness against the official BipBip C++ reference (five vectors each), report FPGA resource utilization on Xilinx Artix-7 (3,356 LUTs, 16.1% of device; crypto logic ~79% of LUTs), and confirm end-to-end operation on hardware.

## 4. 方法详解

### 4.1 Cache 架构设计
- Direct-mapped cache：
  - 128 sets
  - 每 line = 256-bit data + tag + valid + dirty
- 地址拆分（见 Section 4.1）：
  - tag: 52 bits
  - index: 7 bits
  - offset: 5 bits

---

### 4.2 BipBip 加密映射机制（核心）

#### 64-bit cache word 分解：
\[
W = T_{hi}(6b) \parallel P(24b) \parallel T_{lo}(34b)
\]

#### 加密过程：
\[
W' = T'_{hi} \parallel \tilde{E}_{K}(P) \parallel T'_{lo}
\]

- 仅 **24-bit P 进入 BipBip**
- 40-bit tweak 提供上下文绑定（地址相关）

📌 特点：
- 不扩展 ciphertext（仍为 64-bit）
- tweak 保持结构绑定（防搬运攻击）

---

### 4.3 Tag 加密与命中机制
- tag 52-bit → padding → 64-bit decrypt
- hit 判定：
  - decrypt stored tag
  - 与 delayed address tag compare
- 本质：
  - **“encrypted lookup metadata”而非 MAC**

---

### 4.4 Pipeline Overlap（关键创新）

#### Read path：
- decrypt + tag compare 并行
- latency = 3 cycles

#### Write path：
- encrypt = 6 cycles
- tag check = 3 cycles
- overlap：
  - cycles 0–2：encrypt + hit detection 并行
  - cycle 3：hit confirmed
  - cycle 6：write commit

👉 关键结论：
> effective write overhead ≈ 3 cycles（见 Table 3）
