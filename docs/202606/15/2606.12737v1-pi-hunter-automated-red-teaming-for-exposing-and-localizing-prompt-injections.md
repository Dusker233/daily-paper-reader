## 1. 问题与背景  
随着大语言模型逐渐发展为能够调用工具、检索外部信息并与环境交互的智能体系统，提示注入攻击从“单轮输入攻击”演化为“系统级漏洞”。外部网页、邮件、API或检索文档中的隐式恶意指令可能在特定交互路径下被激活，从而绕过模型对齐与安全过滤机制。现有方法主要集中在运行时防御或生成成功攻击提示，但缺乏对“注入是如何在系统中传播并被触发”的整体可观测性分析。因此，如何在部署前主动发现隐藏的注入路径，成为智能体安全中的关键问题。

## 2. 核心思路 / 方法  
论文提出 PI-Hunter，一个面向智能体系统的自动化红队审计框架，其目标不是单纯提升攻击成功率，而是系统性暴露潜在的提示注入入口与传播路径。方法首先分析智能体可访问的工具与外部数据源，然后构建具有现实语境的、与源相关的测试用例，并通过反馈驱动的迭代探索逐步优化测试过程。系统会诱导智能体在真实交互中触发检索、处理并暴露隐藏的恶意指令，同时记录工具调用与推理轨迹用于分析漏洞来源。此外，还结合轻量级临时缓解机制，促使系统探索更广泛的攻击面，从而提升覆盖率。

## 3. 结果与结论  
实验表明 PI-Hunter 在多个基准（如 AgentDojo 和 AgentDyn）上能够显著提升漏洞暴露能力与攻击面覆盖范围，并且可以定位更多潜在的注入来源路径。相比现有自动化红队方法，它不仅发现更多多样化的脆弱交互路径，还能在不同模型与攻击设定下保持稳定表现。即使在 Spotlighting、MELON、PIGuard 等防御机制存在的情况下，该方法仍然能够有效识别潜在注入风险，说明现有防御对隐式注入仍存在覆盖不足。

## 4. 局限与适用边界  
从现有文本无法确认该方法在极大规模真实生产环境中的计算成本与可扩展性表现，但其依赖反馈驱动的迭代探索，可能带来较高的系统开销。由于注入路径依赖外部环境与交互轨迹，其效果可能随任务结构和工具设计变化而波动。整体上，该方法主要适用于具有外部检索与工具调用能力的智能体系统，而非纯文本单轮对话模型场景。

## Abstract
Large Language Models (LLMs) are rapidly evolving into agentic systems that interact with external tools and environments, introducing new security risks such as indirect prompt injection attacks through untrusted external sources. Existing defenses mainly focus on blocking malicious content at inference time, and current red-teaming methods primarily optimize attack success. As a result, developers have limited visibility into how latent prompt injections emerge and propagate through agents. We propose PI-Hunter, an automated agentic auditing framework for proactive vulnerability exposure in LLM agents. PI-Hunter constructs realistic source-aware test cases and iteratively evolves them through feedback-driven exploration to induce agents to retrieve and reveal latent malicious instructions embedded within external environments. Extensive experiments across multiple benchmarks, agent architectures, attacks, and defenses demonstrate that PI-Hunter substantially improves vulnerability exposure and attack-surface coverage over strong automated red-teaming baselines, while remaining effective under existing prompt injection defenses.

## 4. 方法详解

### 4.1 整体框架（Figure 1）
PI-Hunter 分为三阶段：

#### （1）静态分析（Interaction Surface Mapping）
- 输入：agent A + tool set I + external sources S
- 输出：
  - tool-source graph
  - 可访问接口集合
- 目标：确定所有潜在 ingestion path

---

#### （2）源感知测试生成（Source-aware Test Cases）
构造查询集合 Q，使其最大化覆盖：
- source s ∈ S
- tool i ∈ I
- latent payload p

关键目标：
$$
\max_Q \; \text{Exposure}(P | Q, S, I)
$$

特点：
- 模拟真实用户行为
- 强调“触发路径”而非“攻击成功”

---

#### （3）反馈驱动进化搜索（Evolutionary Exploration）
核心机制：
- 执行 query → 得到 agent trajectory
- 记录：
  - tool calls
  - retrieved documents
  - reasoning traces
- 用反馈进行 mutation：
  - 扩展 query 多样性
  - 强化未探索路径

---

#### （4）轨迹审计与局部缓解
- 识别：
  - injection activation point
  - source-to-reasoning propagation path
- 对已验证 source：
  - 临时 mitigation（减少重复探索）
- 目的：提高 coverage（避免局部最优）
