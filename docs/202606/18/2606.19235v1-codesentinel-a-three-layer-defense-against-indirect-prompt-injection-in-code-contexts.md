## 1. 问题与背景  
随着代码大语言模型广泛接入 GitHub、文档与 RAG 等外部代码上下文，攻击者可以在评论、字符串或标识符中隐藏指令，形成间接提示注入风险。这类攻击不同于直接越狱，它利用外部代码被模型读取的过程进行污染，使模型在看似正常的代码中执行恶意意图。由于现有关键词过滤、文件级困惑度或训练式防御难以覆盖隐式触发，这一问题在真实工程部署中变得尤为关键。

## 2. 核心思路 / 方法  
论文提出 CodeSentinel，一个面向推理阶段的三层代码安全防护框架，将代码视为结构化输入而非纯文本处理。系统首先使用 Tree-sitter 将代码解析为语法树，并定位评论、字符串、标识符及“语义弱相关但对模型显著”的高风险节点。第一层进行基于规则与结构的预过滤，捕捉显式异常与可疑模式；第二层在 CST 节点粒度上进行动态 Min-K% 似然异常检测，以识别统计分布异常片段；第三层通过节点扰动分析评估其对模型输出的实际影响，从语义行为角度检测触发器。最终对被判定节点进行归一化清理或替换后再输入下游模型，从而实现多机制联合防护。

## 3. 结果与结论  
实验覆盖六类最新攻击方法，结果显示 CodeSentinel 在节点级 F1 上达到约 0.80，整体优于 CodeGarrison、DePA 和 KillBadCode 等基线方法。在对抗优化攻击下仍保持稳定性能，但在部分自适应攻击中 F1 会下降至约 0.62–0.74 区间。总体结论表明，多层结构化检测能够有效提升对间接提示注入的鲁棒性。

## 4. 局限与适用边界  
方法在面对对抗性优化攻击时性能仍会下降，例如复制触发器或上下文优化会削弱节点影响评估效果。由于依赖语法树解析与启发式评分机制，在不同 tokenizer 或复杂代码结构下可能出现误差与误报问题。从现有文本无法确认其在大规模工业级多语言代码库中的长期稳定性表现。

## Abstract
Code large language models increasingly retrieve external code context from repositories, documentation, issue threads, and coding-agent environments, creating an indirect prompt-injection surface where attackers hide instructions in comments, strings, identifiers, or decoy code. We propose CodeSentinel, a three-layer inference-time sanitizer. It uses Tree-sitter to extract high-risk model-facing CST nodes, then combines syntax-guided pre-filtering, CST-guided Dynamic Min-K\% scoring, and node perturbation analysis to detect adversarial and natural-looking semantic triggers. Detected nodes are removed or neutralized before reaching the downstream Code LLM. Across six recent attack families, \CodeSentinel achieves 0.80 average node-level F1, outperforming CodeGarrison, DePA, and KillBadCode.
