## 1. 问题与背景  
该研究关注大型语言模型在“智能体化”（agentic systems）场景中与外部工具、检索源和动态环境交互时产生的提示注入（prompt injection）安全风险。随着模型从单一对话系统扩展为可调用外部数据源与工具的系统，恶意指令可能被嵌入在网页、邮件或检索文档中并间接触发，从而形成系统级漏洞。现有防御主要聚焦推理时过滤，而现有红队方法又多以“攻击成功率最大化”为目标，导致对潜在注入路径缺乏可解释性与系统性暴露能力。

## 2. 核心思路 / 方法  
论文提出 PI-Hunter，一个面向智能体系统的自动化审计框架，用于主动暴露潜在提示注入漏洞，而非单纯生成攻击提示。其核心机制是构造“source-aware”测试用例，并通过反馈驱动的迭代探索，引导智能体在真实交互中逐步检索并暴露隐藏在外部环境中的恶意指令。系统会分析工具接口与外部来源结构，生成多轮演化测试，并跟踪工具调用与推理轨迹以定位注入传播路径。同时，框架通过对已验证注入源施加轻量级临时缓解策略，扩大对未探索攻击面的覆盖，从而提升审计深度与广度。

## 3. 结果与结论  
实验在多个基准（如 AgentDojo 与 AgentDyn）、多种模型与攻击设置下表明，PI-Hunter 相较强基线显著提升了漏洞暴露能力与攻击面覆盖范围。结果显示其在源定位与恶意指令暴露方面表现更稳定，即使在 Spotlighting、MELON、PIGuard 等现有防御机制下仍能有效发现潜在注入路径。整体结论是，仅依赖攻击成功率评估不足以刻画智能体安全性，需要系统级、过程级的主动审计方法。

## Abstract
Large Language Models (LLMs) are rapidly evolving into agentic systems that interact with external tools and environments, introducing new security risks such as indirect prompt injection attacks through untrusted external sources. Existing defenses mainly focus on blocking malicious content at inference time, and current red-teaming methods primarily optimize attack success. As a result, developers have limited visibility into how latent prompt injections emerge and propagate through agents. We propose PI-Hunter, an automated agentic auditing framework for proactive vulnerability exposure in LLM agents. PI-Hunter constructs realistic source-aware test cases and iteratively evolves them through feedback-driven exploration to induce agents to retrieve and reveal latent malicious instructions embedded within external environments. Extensive experiments across multiple benchmarks, agent architectures, attacks, and defenses demonstrate that PI-Hunter substantially improves vulnerability exposure and attack-surface coverage over strong automated red-teaming baselines, while remaining effective under existing prompt injection defenses.

## 4. 方法详解

### 4.1 总体框架（3阶段）

PI-Hunter = 三段式 pipeline：

#### (1) Static Interaction Mapping
- 分析 agent：
  - tools（search_web / email / retrieval）
  - external sources S
  - interface I
- 构建 source-tool graph

#### (2) Source-aware Evolutionary Exploration
核心循环：
- 初始化 query set \(Q\)
- 执行 agent interaction trajectory：
  - tool calls
  - retrieved content
  - reasoning trace
- 计算反馈信号：
  - 是否触发 injection exposure
  - 是否进入 vulnerable ingestion path
- mutation 更新：
  - 基于 mutation operators（见 Table 6, 7）

可抽象为：
\[
Q_{t+1} = \text{Mutate}(Q_t, \text{feedback}(A(Q_t, S)))
\]

#### (3) Ingestion Path Localization
目标不是 binary attack success，而是：
- 找到 tuple：
\[
(s, i, p)
\]
其中：
- s = source
- i = tool/interface
- p = latent injection

输出：
- injection propagation trace

### 4.2 关键机制

#### A. Latent Exposure Objective
- 强调“触发潜在指令”而不是直接攻击

#### B. Source-Tool Disambiguation
- 区分：
  - source问题 vs tool logic问题

#### C. Transient Mitigation
- 对已发现 injection source 临时“降权”
- 促使探索未覆盖区域（类似 exploration shaping）
