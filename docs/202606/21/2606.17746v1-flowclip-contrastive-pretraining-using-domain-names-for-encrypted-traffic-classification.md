## 1. 问题与背景

论文关注加密网络流量分类问题，即在无法访问明文内容、域名信息和丰富传输层特征的情况下，仅利用可观测侧信道特征识别流量所属域名。随着 DNS over HTTPS、TLS Encrypted Client Hello（ECH）以及 QUIC 协议的大规模部署，传统基于端口号、深度包检测和显式标识符的方法逐渐失效。与此同时，现有研究还面临数据泄漏、特征不可泛化、应用标签定义不统一等问题，因此需要能够在真实部署环境和时间分布变化下学习稳定流量表示的新方法。

## 2. 核心思路 / 方法

论文提出 FlowCLIP，一种借鉴 CLIP 思想的对比预训练框架，用于从加密流量中预测域名。方法仅使用包到达时间间隔、包大小和包方向等侧信道特征作为输入，通过流量编码器和域名文本编码器分别将流量序列与原始域名映射到同一表示空间，并利用对比学习目标拉近匹配样本、拉远不匹配样本。与传统直接分类不同，FlowCLIP将原始域名作为文本监督信号，利用域名层级结构进行表示学习。预训练完成后冻结流量编码器，仅通过线性分类头完成下游域名分类任务，并通过自动域名规范化流程构建标签空间，减少人工定义应用类别带来的偏差。

论文在大规模 QUIC 流量数据集上进行了时间划分实验，使用第 1 周流量训练，并在第 2 至第 4 周流量上测试，以评估时间分布漂移下的泛化能力。实验结果表明，FlowCLIP在后续测试周中优于包括 XGBoost 和 1-NN 在内的竞争性机器学习基线模型。作者据此认为，原始域名能够作为有效的文本监督信号，通过对比预训练学习到具有迁移能力和时间鲁棒性的加密流量表示。

## Abstract
Network traffic classification enables website fingerprinting, intrusion detection, and Quality of Service management. However, developing methods that capture stable and generalizable traffic patterns under realistic deployment conditions remains challenging. We introduce FlowCLIP, a contrastive pretraining framework for domain name prediction from encrypted traffic using only side-channel features: packet inter-arrival times, packet sizes, and packet directions. FlowCLIP uses raw domain names as textual supervision by aligning traffic flow representations with domain name representations through a CLIP-style contrastive objective. The pretrained traffic encoder is then frozen and evaluated through linear probing on canonicalized domain name labels. We evaluate FlowCLIP on a large-scale QUIC traffic dataset using a time-based protocol, where models are trained on Week 1 traffic and evaluated on traffic from Weeks 2-4. FlowCLIP outperforms competitive machine learning baselines across later evaluation weeks, suggesting that raw domain names provide a textual supervision signal for learning transferable encrypted traffic representations.

## 4. 方法详解
### 4.1 任务定义
- 以**双向 flow** 为单位建模，使用前向/反向 5-tuple 聚合流量。
- 每个流 `x_i` 对应一个原始域名 `s_i`，目标是学习流级编码器，使其对下游域名预测可迁移（见正文 Section IV-A）。

### 4.2 输入表示
- 流量侧：只使用 encryption 下仍可见的 side-channel features：
  - packet inter-arrival times
  - packet sizes
  - packet directions
- 文本侧：将**原始域名**作为文本序列输入域名编码器。
- 论文强调域名是**按点分隔的层级结构**，可视作从“更具体”到“更一般”的组件序列（见正文 Section II-A、IV）。

### 4.3 双编码器架构
- **Traffic encoder**：把流量序列编码为向量 `z_t`
- **Text encoder**：把域名编码为向量 `z_d`
- 两者投影到共享表示空间，通过 CLIP-style 对比目标拉近匹配 pair、拉远非匹配 pair。

可用典型 CLIP/InfoNCE 形式理解为：
```text
L = (L_t->d + L_d->t) / 2

L_t->d = - log  exp(sim(z_t, z_d) / tau) / sum_j exp(sim(z_t, z_dj) / tau)
```
其中 `sim(·)` 是余弦相似度或点积，`tau` 为温度系数。

### 4.4 预训练与下游
- 预训练阶段：对齐 `(flow, domain)` 成对样本。
- 下游阶段：**冻结 traffic encoder**，接一个线性分类头做 canonicalized domain label 预测。
- 这样做的目标是检验：预训练得到的表示是否真的“通用”，而不是仅仅记住训练集类别（见正文 Section IV）。

### 4.5 标签规范化
- 作者提出自动 canonicalization，把原始域名映射到统一标签空间，减少人工定义“应用类别”的主观性。
