## 1. 问题与背景
论文关注的是代码大模型在引入外部代码上下文时面临的间接提示注入风险，这类攻击可以隐藏在注释、字符串或标识符中，被模型误当作指令执行。随着代码LLM被广泛用于补全、修复与代码审计，外部RAG或仓库代码的引入使攻击面显著扩大，因此安全性问题变得关键。现有防御方法在关键词过滤、困惑度分析或训练式方案上存在局限，难以有效覆盖隐式或语义级触发。

## 2. 核心思路 / 方法
论文提出 CodeSentinel，一种推理阶段的三层语法语义联合防御框架，将代码解析为CST（Concrete Syntax Tree）结构进行节点级分析。第一层基于语法与规则进行快速过滤，识别明显异常的注释、字符串或结构节点；第二层采用CST引导的动态 Min-K% 似然分析，在节点粒度检测统计异常；第三层通过节点扰动分析评估其对模型行为的影响，从而识别语义触发。系统还结合Tree-sitter解析与早停机制，在不同层级逐步筛选风险节点，并在发送给下游模型前进行净化。

## 3. 结果与结论
在六类最新攻击方法的评估中，CodeSentinel在节点级F1上达到约0.80的平均性能，整体优于CodeGarrison、DePA与KillBadCode等基线方法。在对抗优化攻击场景下，模型仍保持较稳健表现，但F1会下降至约0.62到0.74之间，说明在强自适应攻击下仍存在性能损失。整体结论是语法结构、似然异常与行为扰动三者结合能够显著提升对间接提示注入的防御能力。

## 4. 局限与适用边界
方法在自适应攻击下性能仍会下降，例如复制触发与上下文优化会削弱节点影响评估效果。部分高惊讶但无害的节点可能占用检测预算，从而影响筛选准确性。从现有文本无法确认其在超大规模工业代码库或复杂多语言工程环境中的稳定性边界。

## Abstract
Code large language models increasingly retrieve external code context from repositories, documentation, issue threads, and coding-agent environments, creating an indirect prompt-injection surface where attackers hide instructions in comments, strings, identifiers, or decoy code. We propose CodeSentinel, a three-layer inference-time sanitizer. It uses Tree-sitter to extract high-risk model-facing CST nodes, then combines syntax-guided pre-filtering, CST-guided Dynamic Min-K\% scoring, and node perturbation analysis to detect adversarial and natural-looking semantic triggers. Detected nodes are removed or neutralized before reaching the downstream Code LLM. Across six recent attack families, \CodeSentinel achieves 0.80 average node-level F1, outperforming CodeGarrison, DePA, and KillBadCode.

## 4. 方法详解

### 4.1 总体框架（Figure 1）
流程：
1. Tree-sitter 解析代码 → CST
2. 提取高风险节点：
   - comment / string / identifier / decoy
3. 三层过滤 + early exit
4. sanitize 后输入 LLM

---

### 4.2 高风险节点定义（Section 3.1）
定义风险集合：

- \( D_{risk} = D_{com} \cup D_{str} \cup D_{id} \cup D_{decoy} \)

decoy node 定义（核心创新）：
- 语法合法
- control-flow 不关键
- model-salient 高但程序关联低

---

### 4.3 Layer 1：语法预过滤（Section 3.3）
风险评分：

- regex instruction patterns
- lexical anomalies（Unicode / punctuation）
- graph disconnect：

\[
R_{graph}(n;X)=Sal(n;X)(1-Reach(n))
\]

👉 目标：快速过滤显式 injection payload

---

### 4.4 Layer 2：Dynamic Min-K%（Section 3.4）
核心思想：**node-level NLL anomaly**

- token NLL：
\[
r_i(n) = -\log q_\phi(z_i|X)
\]

- node score：
  - MeanTopK
  - MaxWinLoss
  - MaxSpike

- 动态 Min-K%：
\[
k_{dyn}(n)=f(H(n), |n|)
\]

👉 目标：检测“统计异常但语义正常”的攻击

---

### 4.5 Layer 3：节点扰动分析（Section 3.5）
核心思想：**语义影响 = logit sensitivity**

- 构造 neutralized input \(X(n)\)
- 输出分布差异：

\[
s_3(n)=JSD(\pi_T(X), \pi_T(X(n)))
\]

👉 目标：捕捉自然语言风格的隐蔽 trigger

## 6. 局限性与风险

- **CST依赖性（见 Section 3）**  
  - 需 Tree-sitter 正确解析  
  - 多语言/混合代码可能失效

- **surrogate model 偏差**
  - 使用 gϕ 近似真实 LLM logits  
  - 存在 domain shift 风险

- **adaptive attack vulnerability**
  - copy trigger 可削弱 Layer 3 influence

- **计算开销**
  - Layer 3 perturbation analysis 较重（见 Figure 9）
