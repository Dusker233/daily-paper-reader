## 1. 问题与背景
本论文研究的问题是复杂刑事调查中，大量非结构化证据与自然语言调查意图之间存在的语义鸿沟，使得传统搜索方法难以高效获取相关信息。背景是国际和跨国犯罪调查中，如种族灭绝和反人类罪，调查者需要分析大量证词、访谈记录和通信文档，而现有搜索引擎如 OpenSearch 只能处理结构化查询，无法直接理解自然语言。该问题重要性在于，如果语义鸿沟无法弥合，调查效率低下且可能遗漏关键证据。

## 2. 核心思路 / 方法
论文提出了一种云原生微服务架构，将大型语言模型（LLM）整合到“Human-in-Control”工作流程中，用于将自然语言查询转换为语法有效的 OpenSearch DSL 表达式。方法包括混合检索策略，将基于 BM25 的词汇搜索与语义向量嵌入相结合，以提升对间接表达和语义多样化的捕获能力。系统部署在私有云环境中，通过容器化和微服务设计实现高安全性与可扩展性，并采用文档语义单元划分和 Chain-of-Thought 提示策略以改善长文本查询的逻辑一致性。与其他方法相比，其创新在于以人为主控、LLM 辅助生成 DSL 查询的架构设计，以及混合检索策略在调查场景下的应用。

## 3. 结果与结论
论文通过使用 Enron 邮件数据集验证了系统的技术可行性，并设计了模拟语义鸿沟的搜索场景，测试了词汇、语义和混合检索的性能。初步结果显示，混合检索系统在 Recall@100 指标上优于纯词汇或纯语义方法，证明其在捕获间接表达和语义复杂查询方面更具鲁棒性。核心结论是，该架构为未来实证评估提供了可行的技术基础，并展示了 LLM 在受控调查搜索中的潜力。

## 4. 局限与适用边界
主要局限是由于法律和伦理限制，系统尚未在真实调查数据上进行验证，仅在 Enron 数据集上测试。适用边界为私有云环境下的受控调查场景，需要调查人员保持对搜索流程的主控。

## Abstract
Complex criminal investigations are often hindered by large volumes of unstructured evidence and by the semantic gap between natural language investigative intent and technical search logic. To address this challenge, we present a design and feasibility study of a cloud-native microservice architecture tailored to private-cloud deployments, contributing to research in secure cloud computing and leveraging modern cloud paradigms under high security and scalability requirements. The proposed system integrates Large Language Models into a "Human-in-Control" workflow that translates natural-language queries into syntactically valid OpenSearch Domain-Specific Language expressions. We describe the implementation of a hybrid retrieval strategy within OpenSearch that combines BM25-based lexical search with nested semantic vector embeddings. The paper focuses on system design and preliminary functional validation, establishing an architectural baseline for future empirical evaluation. Technical feasibility is demonstrated through a functional prototype, and a rigorous evaluation methodology is outlined using the Enron Email Dataset as a structural proxy for restricted investigative corpora.

## 4. 方法详解

### 系统架构（见 Figure 1）
- **Presentation Layer**: Next.js SPA，支持 SSR 与异步通信。
- **Orchestration Layer**: FastAPI API-Gateway，异步请求处理，状态管理通过 PostgreSQL（案件管理）和 Redis（任务队列）。
- **Asynchronous Processing Layer (Worker)**: Redis 队列，Python RQ 处理 CPU 密集型解析，向量化交由 OpenSearch ML 节点。
- **Generative Logic Layer**: Langflow 低代码管理提示链，运行本地 LLM（Llama 3 / Mixtral via vLLM），确保数据不出私有云。

### 语义分割与索引策略
- **Heuristic Chunking**: 针对非标准文本，正则检测语义边界。
- **Disentanglement**: 针对通信数据（Enron 邮件）拆分转发链条，保留 Level 1 结构化信息用于过滤，Level 2 表示语义嵌入。
- **Hybrid Indexing**: OpenSearch 中混合索引：
  - Level 1: BM25 全文词汇索引。
  - Level 2: 向量嵌入语义索引。
  - 查询结果通过 Score Fusion 综合词汇与语义权重（Section III-C）。

### 关键公式（Score Fusion 简化表示）
$$
\text{Score}_{hybrid} = \alpha \cdot \text{Score}_{BM25} + (1-\alpha) \cdot \text{Score}_{Vector}
$$
- $\alpha$ 权重可调，用于优化 Recall@100（Section IV）。

## 5. 实验分析

### 主实验结果
- 数据集：Enron 邮件数据集（Section IV）。
- 场景：模拟语义鸿沟，5–10 个抽象调查意图查询。
- 结果：
  - **混合检索** Recall@100 优于纯词汇或纯语义策略。
  - 显示在间接表述、情绪或上下文依赖查询下的稳健性。
- 消融实验：
  - 单独 BM25（Level 1）和单独向量（Level 2）性能较低。
  - Score Fusion 调节 $\alpha$ 显著影响召回率（Section IV）。

| 配置 | Recall@100 | 说明 |
|------|------------|------|
| BM25 仅 | 较低 | 易遗漏间接表达 |
| Vector 仅 | 中等 | 捕获语义，但可能上下文缺失 |
| Hybrid (Level1+2) | 最高 | 综合优势，兼顾间接和语义多样性 |
