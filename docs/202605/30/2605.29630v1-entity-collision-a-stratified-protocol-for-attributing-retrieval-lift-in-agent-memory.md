## 1. 问题与背景

论文关注代理（Agent）记忆系统中的检索评测问题，即现有基准测试报告的单一 hit@k 指标无法区分检索性能究竟来自词汇重叠（lexical leakage）还是来自向量嵌入模型本身。作者指出，现有评测通常同时混合不同类型的记忆查询（如偏好、项目、工具、服务等），并且查询与答案之间往往存在明显实体词重叠，导致 BM25 等词法检索器天然占优。由于部署 Agent Memory 系统时需要在模型成本、延迟和召回率之间做权衡，因此准确识别嵌入模型真实带来的检索增益具有实际意义。

## 2. 核心思路 / 方法

论文提出 Entity-Collision 评测协议，其核心思想是在构造评测集时让所有干扰项与正确答案共享相同实体词，从设计上固定 BM25 的词法检索下界，使超越 BM25 的性能提升能够被归因于嵌入模型本身。同时，作者按照 discriminator tag 对查询进行分层，将 preference、project、technical、service、tool 等不同类别分别评测，避免类别混合掩盖真实差异。实验在 5 类标签、3 种嵌入器以及 5 个 collision 强度等级上进行，并采用 paired bootstrap 95% 置信区间统计结果。该方法最大的创新在于同时解决“词汇泄漏”和“标签混合”两个评测混淆因素，从而获得更具解释性的检索能力归因结果。

## 3. 结果与结论

实验发现存在明显的“双轴模式”：256 维 Hash Trigram 仅在工具、服务等封闭词汇表的词法型任务中、且高碰撞条件下带来收益，而在意图型查询上几乎无效；MiniLM-384 在整体上表现最稳定。进一步引入参数量约为 MiniLM 2.7 倍的 BGE-large 后，结果并未统一提升，BGE 在 project 等意图型任务上优于 MiniLM，但在 tool 和 technical 等词法型任务上反而显著落后。LongMemEval 上的实验复现了这一现象，其中单会话偏好记忆的 hit@1 仅为 0.367，而整体水平约为 0.81。作者据此认为，编码器容量并非决定因素，封闭词汇场景可以采用低成本哈希表示，而意图型查询则需要稠密语义编码器。

## 4. 局限与适用边界

论文大量依赖作者构建的合成 Entity-Collision 数据和 Engram 测试平台，因此结论向真实开放环境的泛化程度仍需更多验证。作者虽然在 LongMemEval 和 LoCoMo 上进行了复现，但从现有文本无法确认更多检索架构（如 ColBERT、SPLADE 等）在该协议下的表现。该协议主要适用于需要分析检索器贡献来源的 Agent Memory 场景，而非直接衡量完整系统端到端能力。

## Abstract
End-to-end agent-memory benchmarks report a single hit@k per retriever, confounding lexical leakage (uncontrolled query/gold/distractor entity overlap) with tag-mixing (preferences, services, tools averaged together). We propose entity-collision, a system-agnostic protocol that pins the BM25 floor by construction -- every distractor shares the answer's entity tokens -- and stratifies queries by discriminator tag, so any lift over BM25 is attributable to the embedder. Applied to an open-source agent-memory testbed across 5 tags x 3 embedders x 5 collision degrees with paired-bootstrap 95% CIs, the protocol reveals a two-axis pattern: a 256-d hash trigram helps only on closed-vocabulary lexical tags at deep collision; MiniLM-384 dominates both axes; and a 2.7x-parameter BGE-large does not uniformly improve on MiniLM -- it wins on intent-style queries but loses on lexical ones. Encoder capacity alone is not the binding constraint. The synthetic intent-tag null replicates on LongMemEval (n=500) as a single-session-preference recall cliff. Adaptive vector-weight routing on LoCoMo is a measured null: 11.7pp of oracle headroom exists, but no signal we tested recovers it. All 26 result tables and 37 reproduce scripts are version-controlled and verified by a public registry; the protocol is exercised on a deterministically governed memory testbed (event-sourced decision log, DAG-state-machine schema lifecycle) so every reported CI is reproducible byte-for-byte from the ingest stream.

## 2.1 问题与动机：现有评测无法正确归因检索收益

作者认为目前 Agent Memory 领域常见评测（如 LongMemEval、LoCoMo）通常只报告一个总体 hit@k 指标，但该指标混杂了两类效应：

### (1) Lexical Leakage

查询与正确答案共享实体词，而干扰项不共享实体词。

例如：

```text
Query: Alice 使用什么云服务？
Gold: Alice uses AWS
Distractor: Bob uses Azure
```

此时 BM25 仅依赖实体词即可命中正确答案。

因此：

> Dense Retriever 的增益可能只是建立在 BM25 已经轻松解决的问题之上。

---

### (2) Tag Mixing

不同类型记忆被混合统计：

- preference（偏好）
- project（项目）
- technical（技术事实）
- service（服务）
- tool（工具）

一个检索器可能：

| 标签 | 表现 |
|--------|--------|
| project | 很强 |
| tool | 很弱 |

最终平均后被掩盖。

作者认为：

> 单一 hit@k 无法指导实际部署中的 Retriever 选型。

（见 Introduction）

# 4. 方法详解

## 4.1 检索单元（Retrieval Cell）

统一检索接口：

```python
engine.recall(query, k, vector_weight=vw)
```

融合得分：

\[
score=(1-vw)\cdot bm25_{norm}+vw\cdot cos\_sim
\]

其中：

- BM25 → FTS5
- Dense Score → Cosine Similarity

权重搜索：

```text
vw ∈ {0.0, 0.3, 0.5, 0.7, 1.0}
```
