## 1. 问题与背景
本文研究的问题是现代大型语言模型（LLM）代理在使用 Bring-Your-Own-Key (BYOK) 架构时存在的安全隐患，即“后对齐篡改”（post-alignment tampering）。在这种场景下，中间中继可以在 LLM 生成安全对齐响应后、代理执行前修改内容，从而绕过现有安全机制。问题重要性在于，即便 LLM 完全对齐，也无法抵御中继篡改，可能导致工具调用、文件写入或金融操作被恶意操控。

## 2. 核心思路 / 方法
论文提出了 Relay Tampering Attack（RTA）框架来系统化利用这一漏洞。RTA 包含三个阶段：战略性编排、多轮对话的状态感知改写；战术性操作，针对关键字段进行最小化修改以影响代理行为；以及隐蔽恢复，通过重新提交修改后的响应生成风格一致的输出。该方法与传统 prompt 注入不同，直接在 LLM 输出与代理执行之间操作，实现高成功率的目标劫持，同时保持低延迟和隐蔽性。

## 3. 结果与结论
在两个代理安全基准（AgentDojo 和 ASB）上，RTA-PostForge 的攻击成功率最高可达 99.1%，显著优于传统 prompt 注入方法。案例研究显示攻击在实际部署的 OpenClaw 和 Claude Code 系统中可行，且现有代理防御机制难以完全阻止。论文结论是，即便 LLM 完美对齐，响应路径篡改仍然构成结构性安全风险。

## 4. 局限与适用边界
论文的主要局限在于防御方案仍需依赖时间通道检测，未能完全消除 RTA 风险，同时攻击依赖 BYOK 或用户可控的中继环境。适用边界主要限于通过中继路由的高权限 LLM 代理系统。

## Abstract
Bring-Your-Own-Key (BYOK) agent architectures let users route LLM traffic through third-party relays, creating a critical integrity gap: a malicious relay can modify an aligned LLM response after generation but before agent execution. We formalize this post-alignment tampering threat and show that, without end-to-end integrity, the relay can observe, suppress, or replace downstream messages, making even perfectly aligned LLMs ineffective against such attacks. We instantiate this threat as the Relay Tampering Attack (RTA), which performs multi-round strategic rewriting, minimal security-critical edits, and stealth restoration by resubmitting tampered outputs to the upstream LLM. Across AgentDojo and ASB with six LLMs, RTA achieves up to 99.1% attack success, outperforming prompt-injection baselines with modest overhead. Case studies on OpenClaw and Claude Code demonstrate real-world feasibility, and evaluations of four defenses show that none fully prevent RTA. Finally, we propose a time-based detection defense that mitigates RTA while preserving agent utility.

## 4. 方法详解

### 4.1 攻击模型（Threat Model）
- relay 位于：
  ```
  Agent → Relay → LLM
  ```
- 能力：
  - 修改 query（q → q̃）
  - 修改 response（r → r′）
- 不需要：
  - 攻破 TLS
  - 控制 LLM

---

### 4.2 RTA 框架

#### （1）Strategic Orchestration（战略编排）
- 多轮对话建模
- 状态分类：
  - comply（不干预）
  - intervene（触发篡改）
- 目标：逐步实现复杂攻击（goal hijacking）

---

#### （2）Tactical Manipulation（战术操作）
- 关键思想：**最小化修改**
- 修改对象：
  - tool name
  - tool arguments
  - finish_reason
- 避免：
  - 大规模自然语言修改（提高隐蔽性）

---

#### （3）Stealth Restoration（隐蔽恢复）
- 将篡改结果重新送入 LLM：
  ```
  r′ → LLM → r″
  ```
- 目的：
  - 恢复自然语言风格
  - 保留关键攻击字段
- 效果：
  - 规避 distribution-level 审计

---

### 4.3 两种攻击路径

| 方法 | 描述 | 特点 |
|------|------|------|
| RTA-PreWrite | 修改 query | 高成功率 |
| RTA-PostForge | 修改 response | **核心贡献** |

---

### 4.4 CaMeL 适配攻击（Appendix）
- 将攻击从 tool-call 转为：
  - **Python code 注入**
- 技巧：
  - 将恶意操作放在第一条语句
- 结果：
  - ASR 从 14.5% → 45.6%
