## 1. 问题与背景

论文关注的是如何在“不可信网络 + 多机构联邦部署”环境下，为分布式高性能计算（HPC）工作流提供可验证的机密通信与策略执行能力。现有 TEE（如 Intel TDX、Arm CCA）只能保证单机虚拟机隔离，但无法把 attestation（远程证明）与跨机器的数据流调度绑定起来，因此攻击者仍可能在解密后通过 hypervisor 或网络命名空间篡改数据流向。传统 RA-TLS 等方案虽然能建立安全通道，但其策略执行位于用户态，存在 syscall、上下文切换和 LibOS 开销，难以满足 100GbE 级高吞吐场景。论文因此试图解决“如何在保持硬件可验证性的同时，实现接近原生性能的分布式机密网络互连”这一问题。

## 2. 核心思路 / 方法

论文提出 Janus，一个面向分布式 TEE 的“split-TCB”架构，将远程证明与高速数据转发拆分为控制面和数据面。控制面运行 MAKE（Mutually Attested Key Exchange）协议，通过硬件 attestation 绑定会话密钥；数据面则将经过测量的 eBPF 程序部署在 guest kernel 内核路径中，以透明方式拦截和加密 UDP 流量，实现内核级策略执行。与传统 RA-TLS 把加密逻辑放在用户态不同，Janus 将 enforcement 下沉到受测量保护的 guest kernel，从而避免 LibOS 与用户态边界带来的性能损耗。论文还提出 epoch-based policy versioning 与 lock-free epoch synchronization，用于在工作流更新或密钥轮换时避免异步策略漂移导致的非法通信。整体上，Janus 的创新点在于把硬件 attestation、SEAM-gated key release 与 eBPF 内核数据面结合，形成一个兼顾可验证性与高吞吐的 confidential federated interconnect。

## 3. 结果与结论

实验基于 Google Cloud Sapphire Rapids（Intel TDX）实例完成。微基准结果显示，Janus 的 eBPF 数据面稳态处理开销约为每包 6 μs，相比原生未加密网络仅增加 13–15 μs 绝对延迟，而传统用户态 RA-TLS 的额外延迟达到 137–147 μs。分布式 ResNet-18 联邦学习流水线实验中，Janus 相比明文 TCP 仅带来 6.1% 执行开销，而用户态方案达到约 62% 的性能损失。论文还表明，100 节点集群的 attestation 与密钥初始化可在 1.5 秒内完成，并能在不中断 UDP/FOU 通信的情况下完成密钥轮换。作者据此认为，Janus 能以接近原生性能的方式实现跨不可信网络的可验证机密工作流。

## 4. 局限与适用边界

论文明确指出，Janus 更适用于“稀疏拓扑、长生命周期”的分布式流水线，而不适用于高密度 O(N²) collective 通信，因为当前硬件 quoting enclave 存在串行化瓶颈。其设计还依赖 guest kernel 被纳入 TCB，因此相比最小化 TCB 的 SGX 类方案，会扩大可信边界。从现有文本无法确认其在复杂多租户环境、动态容器编排或高频短任务场景下的稳定性与扩展性。

## Abstract
Confidential high-performance computing orchestrates workloads across federated domains, yet existing frameworks rely on high-overhead user-space library operating systems or assume single-host execution. We propose \codename, an architecture federating Trusted Execution Environments via a split Trusted Computing Base (TCB) design. It couples a hardware-isolated Control Plane executing Mutually Attested Key Exchange (\make) with a measured guest-resident extended Berkeley Packet Filter (eBPF) Data Plane. By anchoring cryptographic key release to hardware measurements and executing enforcement in the kernel, \codename\ achieves native-speed encrypted routing. Empirical evaluation demonstrates a steady-state enforcement cost of $6\,μ$s per packet, imposing a $13$--$15\,μ$s absolute latency overhead. On distributed pipelines, \codename\ incurs just a $6.1\%$ execution penalty over plaintext baselines, bypassing the $62\%$ penalty of user-space counterparts. The system initializes a 100-node cluster in under 1.5 seconds, providing an efficient confidential interconnect for long-running workflows.
