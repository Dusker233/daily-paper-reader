ABSTRACT 

Logs are ubiquitous in modern systems. Unfortunately, their un-structured nature in flat sequences limits understanding of exe-cution behaviors, hindering effective anomaly diagnosis. To ad-dress this, Krone introduces a novel hierarchical log abstraction which transforms flat log sequences into semantically coherent units across entity, action, and status levels. Building on this abstrac-tion, Krone introduces a hierarchical orchestration framework that decomposes flat log sequences into hierarchical execution units and performs modular detection over them. It executes and optimizes the modular detection tasks across levels, enabling precise anomaly detection, localization, and explanation with selective invocation of LLM-based reasoning. In this work, we present Krone-viz , an inter-active visualization system based on Krone , which makes hierarchi-cal log analysis interpretable and actionable for software engineers and system operators. Demonstrated on the widely used HDFS benchmark dataset, Krone-viz supports: 1) examine hierarchical decompositions of flat log sequences, 2) inspect detection results and abnormal segments identified by Krone with LLM-generated explanations, , and 3) reuse-review-revise knowledge generated by LLMs with human in-the-loop guardrails. The code of Krone-viz is available at https://github.com/LeiMa0324/KRONE_Demo_official, and we deploy a live demo at https://leima0324.github.io/KRONE_ Demo_official. 

1 INTRODUCTION 

Motivation. In modern data-intensive infrastructures, logs serve as a primary source for understanding system execution and di-agnosing anomalies. Effective log analysis enables timely system monitoring, rapid issue resolution, and reliable operation at scale, making it essential for maintaining high-performance and depend-able services. However, as shown in Figure 1 left, most log anomaly detection methods [ 1 –3] operate on flat log sequences and produce a single anomaly score (label) for an entire log sequence. Further, they have limited support for interpreting results and localizing anomalous segments. Recent LLM-based approaches [ 5, 6 ] improve interpretability through natural language explanations, but con-tinue to operate on flat log sequences. Plus, they suffer from limits

Our work: Krone Framework. Krone [4] (accepted at IEEE ICDE 2026) introduces the first hierarchical log abstraction that discovers and reconstructs execution semantics directly from logs. This abstraction enables efficient, effective, and interpretable log anomaly detection. Figure 1 compares Krone with traditional flat log anomaly detec-tion paradigms. The key insight of Krone is that system executions follow hierarchical structures with nested components and opera-tions. Accordingly, Krone defines a three-level semantic hierarchy: Entities correspond to system components, Actions capture oper-ations, and Statuses reflect the outcome of each action. Based on this hierarchy, Krone decomposes log sequences into atomic and reusable execution segments and formulates anomaly detection as modular tasks across semantic levels, enabling precise localization of anomalies within execution contexts. To leverage foundation models while minimizing cost, Krone 

adopts a lightweight pattern-matching detector for fast filtering known normals and selectively invokes LLM-based reasoning for uncertain cases. Krone maintains a hierarchical knowledge base that reuses the modular detection results to support knowledge-empowered analysis with further reduction in LLM calls. 2 THE KRONE FRAMEWORK 

We briefly introduce the Krone framework and its core innovations. 

2.1 Krone Framework Overview 

Figure 2 presents an overview of the Krone framework, which consists of four modules. (1) Hierarchy Extraction uses LLMs to extract the entity–action–status semantics from log templates 1 to construct the semantic hierarchy, namely Krone-Tree . (2) Using 

Krone-Tree , Log Sequence Decomposition transforms flat logs into hierarchical execution units ( Krone Seqs ). (3) Modular Detection 

performs anomaly detection on each Krone Seq using lightweight pattern matching with selective LLM reasoning, orchestrated in a bottom-up manner with early stopping. (4) Knowledge Base stores detection results and explanations for reuse, reducing redundant LLM calls. Krone-viz visualizes the intermediate outputs of each module, which is introduced in Sec. 3. 

2.2 Core Innovations of Krone 

Krone is built on three core innovations: (1) the Krone Log Ab-straction Model , (2) the Hierarchical and Modular Anomaly Detection, and (3) the Knowledge Base for Amortized Detection. 

Innovation 1: Krone Log Abstraction Model . The key in-novation of Krone is a hierarchical abstraction for log modeling that can be instantiated as a dataset-specific semantic hierarchy (see Figure 3). This abstraction is based on the observation that log messages follow a consistent semantic pattern: a status describes an action performed on an entity . For example, Figure 3(a) shows the template “Open session started”, where " 𝑆𝑒𝑠𝑠𝑖𝑜𝑛 ", " 𝑂𝑝𝑒𝑛 ", and "𝑆𝑡𝑎𝑟𝑡𝑒𝑑 " correspond to the entity, action, and status, respectively. Following this abstraction, Krone Log Abstraction Model de-fines a semantic hierarchy, namely Krone-Tree , over all log tem-plates (Figure 3(b)), capturing entities, actions, and statuses along with their relationships. In Krone , this hierarchy is extracted via an LLM-based NER formulation, where LLMs identify entity, action, and status from each template and construct the Krone-Tree . Each leaf status node maps to a single template, while actions and entities group semantically related templates. One key benefit of the Krone-Tree is that it enables decomposi-tion of long log sequences into semantically coherent units at mul-tiple granularities, supporting a divide-and-conquer approach to anomaly detection. Given the Krone-Tree and input log sequences, 

Krone decomposes each sequence into Krone Seqs —contiguous segments represented as node sequences in the hierarchy—across entity, action, and status levels. As illustrated in Figure 3(c)–(d), 

Krone E-seqs , Krone A-seqs , and Krone S-seqs capture transitions at the three levels with the corresponding segment (as corresponding template rows), enabling hierarchical learning of normal patterns and modular anomaly detection within smaller scopes. 

Innovation 2: Hierarchical and Modular Anomaly Detection. 

Krone introduces a hierarchical, modular formulation that de-composes anomaly detection into semantically scoped tasks over 

Krone Seqs , enabling precise localization and scalability. Specifi-cally, each Krone Seq is evaluated against its normal counterparts within a well-defined semantic scope determined by the Krone-Tree . For modular detection, Krone first applies a lightweight pattern-matching (PM) detector to efficiently filter out known nor-mal Krone Seqs , and then augments detection by selectively in-voking LLM-based reasoning to examine the remaining unknown 

Krone Seqs . Using 𝑘 normal Krone Seqs as in-context examples,

The orchestration of modular detection in Krone is guided by two properties of Krone Seqs : higher-level Krone Seqs are com-positions of lower-level ones and incur higher LLM cost due to longer-range dependencies. This motivates a hierarchical, bottom-up strategy that examines Krone S-seqs first and proceeds upward only if no anomaly is detected. Since anomalies propagate through composition, Krone employs early stopping upon detecting the first anomaly to avoid unncessary computation cost. 

Innovation 3: Knowledge Base for Amortized Detection. Our empirical evaluation observes that Krone Seqs are atomic execution units that frequently recur across log sequences, often appearing in different compositions (permutations). This property makes their knowledge inherently reusable: once an Krone Seq is evaluated, its result can be reused across sequences, avoiding redundant LLM invocations. Following the same LLM-cost optimization principles, 

Krone maintains a hierarchical knowledge base that stores LLM-generated artifacts for Krone Seqs , including detection outcomes and explanations. During modular detection, Krone first queries this knowledge base for a given test Krone Seq , invoking the LLM only when no matching entry is found. As stored Krone Seq knowl-edge is semantically grounded and shared across sequences, this design enables substantial amortized cost reduction over time while improving interpretability. Beyond caching, this knowledge base serves as a foundation for continuous refinement: newly detected patterns and human-validated corrections can be incorporated to improve future de-tection and explanation quality. This design elevates LLM usage from per-instance inference to a knowledge-driven process that improves efficiency, interpretability, and adaptability over time. 

3 DEMONSTRATION OF KRONE-VIZ 

In this demonstration, the audience will experience the power of 

Krone through Krone-viz , an interactive system with interlinked, customized views (Figure 4). We showcase Krone ’s core innova-tions and workflows on the real-world HDFS public benchmark, with representative visualizations shown in Figure 4. Krone-viz 

enables effective human-centered analysis by making Krone ’s hi-erarchical decomposition, anomaly localization, LLM-based expla-nations, and accumulated knowledge transparent and actionable. The full interactive experience is available on our demo site 2.Through Krone-viz , the audience actively explores each core step of Krone in the following four stages: 

• Stage 1: Hierarchy Extraction. The audience begins by loading log templates into Krone-viz , which invokes an LLM to extract entities, actions, and statuses and construct the Krone-Tree (Fig-ure 4(a)). The interface displays the resulting hierarchy along with tree statistics, allowing the audience to explore relationships be-tween the Krone-Tree (A1) and log templates (A2). By hovering over nodes, the audience can see associated templates, making the semantic structure of logs explicit. This stage highlights In-novation 1 by showing how Krone transforms flat logs into an interpretable hierarchical abstraction. 

• Stage 2: Training Data Processing. The audience selects a nor-mal log sequence and observes how Krone-viz decomposes it into hierarchical Krone Seqs (A3) aligned with the original sequence (A4) (Figure 4(b)). As the decomposition proceeds, intermediate 

Krone S-seqs are stored and marked as completed at their parent nodes, illustrating the construction of ground-truth execution units. Through this interactive process, the audience learns how normal execution patterns are captured and stored in the knowledge base. 

Krone-viz also provides a batch mode for one-click processing of all training sequences. 

• Stage 3: Hierarchical and Modular Anomaly Detection. The au-dience selects a test log sequence and triggers anomaly detection (Figure 4(c)). Krone-viz decomposes the sequence into test Krone 

Seqs and performs modular detection in a bottom-up manner from status to entity levels, with a progress bar (A5) indicating the cur-rent stage. For each Krone Seq , a pattern-matching detector first searches the knowledge base. If no match is found, the system flags the Krone Seq as potentially anomalous and highlights the corresponding segment (A6). The audience can then invoke the LLM to verify and explain the anomaly (A7). If confirmed, Krone 

stops further analysis and reports the detected anomaly. This stage demonstrates Innovation 2 by enabling precise, cost-efficient anom-aly localization and explanation.

4 CONCLUSION 

We present Krone-viz , an interactive system for hierarchical log anomaly analytics based on Krone . By exposing hierarchical struc-tures, modular detection, and reusable knowledge, Krone-viz en-ables transparent anomaly detection, localization, and explanation. This demonstrates how Krone achieves interpretable and scalable log analysis with efficient cost-aware LLM integration.
